# 项目总览

更新日期：2026-10-11。仓库：[KurolMato/dsp](https://github.com/KurolMato/dsp)。

本项目是一个 Python 桌面音频处理系统，集成语音分析与降噪、音乐人声/伴奏分离、双人重叠语音分离及房间音效。界面使用 Tkinter 和 Matplotlib，处理算法与耗时任务分别放在独立模块和后台任务中。

本文介绍当前实现；安装细节见 [README](../README.md)，历史改动与实验条件见文末的专题文档。

## 1. 功能与工作区

右侧有三个工作区；左侧控制面板分为「处理」「数据」「模型」「音效」四个标签页。

| 工作区 | 已实现功能 |
|---|---|
| 语音处理 / 信号分析 | 录音、导入、播放、端点检测、回声、倒放、时域波形、频谱、谱图、带阻滤波及四种降噪方案对比 |
| 音乐分离 / 分轨混音 | 分离人声与伴奏，或分离人声、鼓、贝斯、其他四轨；同步试听、定位、音量、静音、独奏、混音与音轨导出、历史结果 |
| 双人语音分离 | 将两人同时说话的混合录音分成两条匿名音轨；同步试听、逐轨降噪、软噪声门、原始/增强结果切换、导出与历史结果 |

左侧「音效」页为语音工作区提供添加混响和 WPE 去混响，可以选择原信号或当前处理结果作为输入。

图形支持子图放大、滚轮缩放和拖动平移。降噪对比窗口每行的「放大看频谱」只显示**原信号 + 该方案**，频谱和时域波形各两条曲线；「全部方案叠加」按钮显示完整对比。试听后可选择一个方案作为当前输出。

## 2. 主要算法

### 语音降噪与滤波

| 方法 | 当前实现 | 使用方式 |
|---|---|---|
| GTCRN 预训练降噪 | 16 kHz 神经网络语音增强，使用 ONNX Runtime 推理；内部重采样后恢复输入采样率与长度 | 直接使用随仓库提供的小型模型，GUI 不训练 GTCRN |
| 自训练 MLP | NumPy 实现前向、反向传播和 Adam；用时频特征及时间上下文预测掩蔽，网络和特征配置从模型元数据读取 | 使用已有版本，或导入自己的干净语音和噪声重新训练 |
| 经典谱减法 | 平滑最小值统计估计噪声功率谱，结合谱减和维纳平滑 | 无需训练；默认先检测持续窄带干扰，按需自动陷波后再谱减 |
| 串联 GTCRN → MLP | **GTCRN 输出作为 MLP 输入**，执行两级顺序处理；MLP 特征仍遵循该版本的训练配置 | 两个模型均可用时参加多方案对比 |

当前串联流程：

```text
带噪语音 → GTCRN 增强 → 自训练 MLP 增强 → 处理结果
```

训练参数 `--noise-prefix gtcrn` 另用于训练采用 GTCRN 残差特征的 MLP 版本，推理时必须使用相同特征配置。它与界面中的两级串联是不同的配置层次。

「谱减法自动陷波」默认开启：检测持续窄带峰及相关干扰，符合条件才滤波，未检测到时跳过。关闭后使用手动带阻参数；界面可预览检测结果和滤波器响应。传统 STFT 使用 512 点窗、128 点帧移；GTCRN 和房间音效使用各自的分析配置。

### 音乐分离

| 模型预设 | 输出 |
|---|---|
| VR：`1_HP-UVR` | 人声、伴奏 |
| RoFormer：`bs_roformer_voc_hyperacev2` | 人声、伴奏 |
| HTDemucs4 | 人声、鼓、贝斯、其他；另外合成伴奏 |

音乐模块通过独立 worker 调用 pymss。输出恢复原采样率、时长及单/双声道；分轨共用播放游标，混音支持统一峰值保护。四轨模式的伴奏由鼓、贝斯和其他合成，默认混音不会再重复叠加派生伴奏与原曲。

### 双人分离与逐轨后处理

使用 SpeechBrain 的 `speechbrain/sepformer-wsj02mix`，模型内部采样率为 8 kHz。长音频按块处理，并根据重叠区波形匹配两条音轨的顺序；不做声纹识别，也不指定 A/B 身份。

两条分离音轨分别支持 GTCRN 轻度增强和软噪声门。默认降噪强度 35%，噪声门关闭；可以独立调整开关和参数。重新处理始终从原始分离结果开始，试听可切换原始/增强版本，导出保留原始两路。

`samples/speaker_reference/` 提供六秒混合参考、已知两路原音、模型分离结果及增强结果，可从双人工作区加载演示。

### 混响与去混响

添加混响使用早期反射与衰减尾音构造房间响应，再与输入卷积并混合干湿声；可调衰减时间、湿声比例、预延迟和高频阻尼。WPE 通过延迟加权线性预测削减晚期混响。

界面处理语音工作区的单声道信号，算法接口支持单/双声道。结果保留原长度；添加混响时超出原文件末尾的尾音截断。

## 3. 启动与资源下载

当前主要验证平台是 **Windows、64 位 Python 3.12、CPU**。主环境 `.venv` 服务语音和音乐功能；双人分离使用独立 `.venv-speakers`，隔离 SpeechBrain / PyTorch 依赖。

```powershell
git clone https://github.com/KurolMato/dsp.git
cd dsp
.\setup_music_windows.bat
# 需要双人语音分离时再执行：
.\setup_speakers_windows.bat
.\run_windows.bat
```

三个 Windows 脚本共用 `bootstrap_windows.ps1`，检测本机解释器和项目环境，必要时保留失效环境并重建。虚拟环境不上传，也不作为跨电脑运行包；每台电脑单独安装依赖。仅基础语音处理可以安装 `requirements.txt`，音乐和双人分离还需要相应扩展依赖。

macOS / Linux 的启动入口为 `run_unix.sh`，环境配置见 README；这些平台及 CUDA 尚未完成与 Windows CPU 相同范围的实测。

| 内容 | 获取位置 |
|---|---|
| 源码、依赖清单、启动脚本、小型降噪模型、参考音频、个人录音 | Git 仓库；个人录音在 `recordings/` |
| 全部模型及本机训练/实验版本 | [Release](https://github.com/KurolMato/dsp/releases/tag/assets-20261010) 的 `all-models.zip`，约 608.5 MB |
| 合成与真实噪声训练数据 | 同一 Release 的 `training-noise-bank.zip`，约 1,051.5 MB |
| 资源校验值 | Release 的 `assets-manifest.json`、`SHA256SUMS.txt`，以及 [资源文件清单](资源文件清单_2026-10-10.json) |

资源包解压到项目根目录，保留 `models/` 和 `models_loo/` 层级。音乐和双人分离也可在界面首次使用时单独下载对应模型。模型包含部分历史实验资产，当前 GUI 功能以第 1、2 节为准。

## 4. 训练与评估

GUI 的训练按钮训练自训练 MLP。干净语音可通过录音、单条导入或批量导入加入 `recordings/`；默认语料发现还会检查示例和已有本机素材。噪声来自程序合成，或通过 `--noise-dir` 指定的真实噪声库。

当前训练脚本使用实际混合噪声残差生成 IRM 标签。训练/验证先按音频内容哈希分组，再切分片段；只有一个来源时按不重叠时间段划分。该划分不等于已经证明跨说话人泛化。

```powershell
.venv\Scripts\python.exe -X utf8 train_model.py --activate
# 使用真实噪声库：
.venv\Scripts\python.exe -X utf8 train_model.py --noise-dir models\noise_bank\real --file-noise-ratio 0.3 --activate
```

新版本默认保存在 `models/runs/`，含权重、训练日志、评估报告和划分清单；可取消训练、重载或切换模型。当前模型指针为 `models/active_model.json`。不同权重版本的训练条件应以其元数据和报告为准。

有干净参考的离线实验可比较 SNR、LSD、SSNR 等指标。实际录音通常没有干净参考，GUI 显示高低能量对比改善、低能量帧下降、高能量帧保留和频谱改变量；这些不能直接当作真实 SNR、语音质量或人声失真。静音、过短或难以区分高低能量时，指标可能无法可靠估计。

小样本自训练、旧标签、旧特征或旧划分条件下的实验数字，不作为当前版本的统一性能结论。分离仍可能残留另一人的声音；逐轨降噪和噪声门不能保证消除串音，过强处理也可能削弱目标语音。WPE 不保证从任意混响录音恢复完整干声。

## 5. 目录与关键模块

| 文件 / 目录 | 职责 |
|---|---|
| `app.py` | 主界面、语音分析、方案选择、训练入口和音效操作 |
| `core/dsp.py` | STFT、端点检测、带阻/自动陷波、谱减法、频谱及基础音效 |
| `core/model.py`、`core/data.py`、`core/corpus.py`、`core/enhance.py` | MLP、数据合成、语料划分、推理及串联 |
| `core/gtcrn.py`、`core/metrics.py`、`core/audio_io.py` | GTCRN、评估及音频读写/播放 |
| `core/room_effects.py` | 房间响应、混响与 WPE |
| `music_panel.py`、`music_worker.py`、`core/music.py` | 音乐分离界面、推理进程、同步混音与任务控制 |
| `speaker_panel.py`、`speaker_worker.py`、`core/speakers.py` | 双人分离界面、推理进程、分块拼接及任务控制 |
| `speaker_postprocess_worker.py`、`core/speaker_cleanup.py` | 逐轨增强、软噪声门及配置校验 |
| `core/tasks.py` | 后台处理与素材版本检查，避免过期结果覆盖新音频 |
| `models/`、`samples/`、`recordings/` | 模型与训练数据、示例/参考音频、录音语料 |
| `results/` | 处理输出、历史清单、导出及本机验证记录；不随 Git 上传 |
| `bootstrap_windows.ps1`、安装/启动脚本、requirements 文件 | 环境检测、依赖安装和启动 |

## 6. 验证与两台电脑同步

常用检查在项目根目录执行：

```powershell
.venv\Scripts\python.exe -X utf8 check_env.py
.venv\Scripts\python.exe -X utf8 smoke_test.py
.venv\Scripts\python.exe -X utf8 verify_interactions.py --plots-only
.venv\Scripts\python.exe -X utf8 verify_portable_startup.py
```

已记录的算法冒烟检查为 16/16、图形交互检查为 23/23、启动迁移检查为 7/7。它们验证对应功能与流程，不代表每段真实录音的听感。房间音效、自动陷波、双人分离和后处理另有 `verify_room_effects.py`、`verify_auto_notch.py`、`verify_speakers.py`、`verify_speaker_cleanup.py`。部分完整回归需要本机模型缓存、独立环境或历史验证资产，克隆代码后不能默认具备全部测试前提。

两台电脑每次修改前先 `git pull --ff-only`，完成后 `git add .`、`git commit -m "修改说明"`、`git push`。Git 同步提交后的文件，不同步编辑过程。Release 模型/数据包需单独下载，不随 `git pull` 更新；依赖变更后按需重新运行安装脚本。
