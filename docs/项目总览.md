## 1. 项目是什么

一个**语音信号处理 + 机器学习降噪**的 Python 桌面应用：

| 能力 | 实现 |
|---|---|
| 音频输入 | 麦克风录音（16 kHz / 可调声道，每条自动归档）、导入 wav/mp3/m4a/flac |
| 基础处理 | 播放、回声、倒放 |
| 分析 | 短时能量端点检测、时域波形、频谱、对数谱图、Butterworth 带阻（陷波）滤波器设计演示 |
| **降噪（核心）** | **4 种方案**：GTCRN 预训练 / 自训练 MLP / 经典谱减法 / 串联融合，可同台对比并任选 |
| 评估 | ΔSNR、对数谱失真（LSD）、分段信噪比（SSNR）、噪声抑制、无参考评估；含理论上限 |

界面：tkinter + matplotlib，4 个坐标轴、14 个按钮；左侧控制面板**按功能分成三个标签页**
（处理 / 数据 / 模型），并有滚动兜底 —— **任何窗口尺寸下都不会有控件被裁掉**；
**单击任意子图可弹出放大窗口**，**鼠标滚轮以光标为中心缩放**（13 档）、
**按住左键拖动可平移**；对比对话框不锁主窗口、可边看边选。

### 1.1 四种降噪方案各是什么（一句话 + 什么时候用）

| 界面按钮 | 方案 | 一句话原理 | 适合场景 |
|---|---|---|---|
| ⑤ | **GTCRN 预训练** | 直接用别人在 DNS3（真实噪声）上训好的小网络，逐帧算出"每个频点保留多少" | 想开箱即用、看重语音保真 |
| ⑥ | **自训练 MLP** | 用你自己的录音 + 合成/真实噪声现场训一个网络，同样输出时频掩蔽 | 想要最强的噪声抑制、速度快 |
| ⑦ | **经典谱减法** | 先估噪声谱，再从带噪谱里减掉（α 过减 + 维纳平滑） | 想可解释、零训练；平稳噪声OK |
| ⑧ | **串联融合** | 先用 GTCRN 估噪声底，再把这份"噪声情报"喂给自训练网络做掩蔽 | 既想压得狠又想保人声 |

### 1.2 串联融合到底在做什么（重点）

**它不是"两次降噪串起来输出"，而是把 GTCRN 当成一个"噪声估计器"。**

```
带噪语音 y (16 kHz)
  │
  ├─① 升采样到 48 kHz（GTCRN 的原生采样率）
  ├─② GTCRN 降噪 → enh48
  │      残差 = y48 − enh48     ← GTCRN 认为"这是噪声"的部分
  │      降回 16 kHz 做 STFT → 得到噪声底估计 N̂（dB，257 × T）
  │
  ├─③ 把 N̂ 当作自训练网络的「特征②噪声底」喂进去
  │      （自训练网络输入 = [带噪对数谱 | 噪声底 | 局部SNR] × 13 帧）
  │
  └─④ 自训练网络输出掩蔽 M → 乘回频谱 → ISTFT → 输出
       注意：GTCRN 的音频输出被丢掉了，只借用它的"噪声感知能力"
```

**为什么有用（实测机制证据）**——两种噪声估计与真实噪声谱的差距（12 用例，DEMAND @5 dB）：

| 噪声底估计来源 | 与真实噪声谱相关系数 | 平均绝对误差 |
|---|---|---|
| **GTCRN 残差** | 0.496 | **4.29 dB** |
| 自研平滑最小值统计 | 0.473 | 6.46 dB |

误差小 2.2 dB，掩蔽网络判断"这点是噪声还是语音"的依据就更准。本质是**零成本迁移学习**：
不下载几千小时数据、不装 PyTorch，只借用已训练模型的噪声感知能力，弥补自己干净语音少。

> ⚠️ 注意：**交付的模型是按"最小值统计"训练的**（元数据 `noise_prefix: ms`）。
> 界面 ⑧ 里的串联会喂给它一个训练时没见过的特征——能跑、也有正收益（+5.84 dB），
> 但没发挥全力。要让串联真正发挥优势，重训时加开关：
> `python train_model.py --noise-prefix gtcrn`（每个样本多跑一次 GTCRN，训练约 15~25 分钟）。

### 1.3 关于训练：GUI 上哪些操作和"训练"有关

| GUI 元素 | 作用对象 | 说明 |
|---|---|---|
| 「训练降噪模型」按钮 | **只训练自训练 MLP** | 用 `recordings/` + 上级目录的干净语音 + 噪声库现场训练 |
| 「重新加载模型」 | **自训练 MLP**（GTCRN 也会顺带重载） | 训练完自动加载，无需手动 |
| 「训练数据」面板（导入干净语音/导入真实噪声/打开数据目录/语料统计） | 训练语料与噪声库 | 只影响自训练模型的训练数据 |
| ⑤ GTCRN | **不可训练** | 预训练模型是固定的 ONNX 文件（0.51 MB），只能推理 |
| ⑦ 经典谱减法 | **无需训练** | 参数是人工设定的（α、β、噪声估计窗长） |

**一句话**：GUI 里所有"训练/语料/模型加载"相关功能，全部只服务于**自训练 MLP** 这一条路线。

## 2. 用到的技术方法

### 2.1 信号处理层（传统方法）
- **分帧与短时能量**：帧长 20 ms / 帧移 10 ms，阈值 0.02 做端点检测；
- **Butterworth 带阻/陷波滤波器**：`buttord` + `butter(..., 'stop')` 设计并绘制幅频响应；
- **谱减法**：`|S|² = max(|Y|² − α|N|², β|Y|²)`，配合**维纳平滑**抑制音乐噪声；
- **噪声功率谱估计（关键改进）**：单帧周期图取最小值对噪声**低估 539 倍**，改为
  **先做 (9 频点 × 11 帧) 盒式平滑、再取最小值、再乘偏置 3.0**，噪声估计才可用；
- **STFT / ISTFT**：512 点窗、hop 128、Hann 窗，重叠相加（OLA）重建。

### 2.2 机器学习层
| 方案 | 方法要点 |
|---|---|
| **自训练 MLP** | 纯 NumPy 手写前向 + 反向传播 + Adam（因为 Python 3.14 装不上 PyTorch）；输入 = 257 频点 × 3 类特征 × 13 帧 = **10023 维**；网络 `10023→256→128→257`，输出 sigmoid 掩蔽；损失用**二元交叉熵**回归**理想比值掩蔽 IRM**；263 万参数，CPU 训练约 8 分钟 |
| **三类输入特征** | ① 带噪对数幅度谱 ② **噪声底估计** ③ 局部信噪比。实测只用①时网络输出接近常数（逐频点相关 0.54），加②③后 ΔSNR 从 +1.42 → +4.04 dB |
| **时间上下文** | 每帧拼接前后各 6 帧（±48 ms）：语音连续、噪声平稳，靠邻域才能判断"这点是语音还是噪声" |
| **GTCRN 预训练** | ICASSP 2024 官方模型（DNS3 上训练，0.5 MB / 48.2K 参数），用 **onnxruntime** 推理、**无需 PyTorch**；原生 16 kHz；逐帧流式（conv/tra/inter 三组状态缓存） |
| **串联融合** | GTCRN 的"输入−输出残差"当噪声底估计，喂给自训练模型的掩蔽网络 |
| **数据集自造** | 干净语音（自己的录音）+ 噪声（8 类程序化合成 + DEMAND 真实场景）→ 按随机 SNR（−5~20 dB）混合 → IRM 标签自动生成；**每个 epoch 现场合成，规模无限、零人工标注** |

### 2.3 工程与验证方法
- **理论上限分析**：掩蔽类方法保留带噪相位，SNR 提升存在硬上限（实测相位上限 +4.88 dB、理想掩蔽 IRM +6.35 dB）——所以评估必须多指标一起看；
- **可控消融实验**：上下文宽度、是否加噪声底特征、训练噪声覆盖广度、是否用真实噪声，逐项对照；
- **泛化检验**：留出噪声类型（排除车内/空调/键盘）+ 留出真实场景（广场/公园），证明不是过拟合；
- **自动化验证**：算法自检 16 项、GUI 全流程 11 步、界面交互 12 项，全部脚本化可复跑。

## 3.1 想给训练集加更多语音，怎么办（三种方式）

自训练模型的语料来源有固定的三处，**不用改代码**：

```
dsp_py/recordings/             ← 界面「① 录音」自动归档 + 「导入干净语音…」+ 批量导入
dsp_py/models/noise_bank/      ← 噪声：合成 8 类 + real/ 真实数据集（「导入真实噪声…」）
E:\dsp\（项目上一级）           ← 原始素材 data.wav / manba.wav
```

| 方式 | 适合 | 操作 |
|---|---|---|
| **① 界面批量导入文件夹** | **推荐**：几百个素材一次搞定 | 左侧「训练数据」→「**批量导入文件夹…（推荐）**」→ 选文件夹（自动递归子目录） |
| **② 界面逐条录音** | 自己念几分钟，环境可控 | 「① 录音」→ 设好时长 → 录；每条自动归档，不覆盖 |
| ③ 界面导入（少量文件） | 几个到几十个文件 | 「导入干净语音…」多选文件 |
| ④ 命令行批量（脚本化） | 想把导入写进脚本/流水线 | `python corpus_tool.py import --from <目录> --recursive` |

界面上的批量导入与命令行**用的是同一个核心函数** `corpus_tool.import_corpus()`，
所以行为完全一致：统一重采样 16 kHz、转单声道、峰值归一化、跳过重复、长度过滤、导入后质检；
界面上会弹一个进度窗口显示 `已处理 x/y（成功 a，重复 b，时长不符 c）`，结束后汇总并提示下一步。

```powershell
# 命令行等价用法（另有 --dry-run 预演、--as-noise 导噪声、zip 压缩包支持）
python corpus_tool.py import --from D:\语音素材 --recursive --dry-run   # 先预演
python corpus_tool.py import --from D:\语音素材 --recursive             # 真正导入
python corpus_tool.py import --from D:\DEMAND --recursive --as-noise   # 导入真实噪声
python corpus_tool.py audit                                            # 导入后体检
```

**训练前会自动筛掉不合格素材**（实测依据）：

| 规则 | 阈值 | 为什么 |
|---|---|---|
| 近乎静音 | 有效样本 < 30% | 麦克风被静音/禁用时误录，当训练输入无意义（实测有一条录音仅 3.4% 有效样本） |
| 底噪偏大 | 静音段/语音段 > −40 dB | 当"干净参考"会教模型保留噪声（实测 `manba.wav` 是 −28.1 dB） |

体检命令 `python check_corpus.py` 会逐个文件列出**时长 / 峰值 / 底噪比 / 有效样本占比**并标出问题项。
被跳过的素材会在训练日志里打印原因，不会静默消失。

**导入多少才够？** 目前约 29 秒可用语音（模型已能工作，但属于"欠拟合"区间）。
经验值：**3~5 分钟**能明显改善，且尽量覆盖**不同环境/不同说话人**，比单纯堆时长更有用。

## 4. 关键结果

**真实 DEMAND 噪声 @5 dB，30 个用例（语音未参与训练）**

| 方案 | ΔSNR | 对数谱失真改善 | 噪声抑制 | 耗时/4 秒 |
|---|---|---|---|---|
| GTCRN 预训练 | −1.16 dB | **+6.30 dB** | 2.8 dB | 296 ms |
| **自训练 MLP（默认）** | **+7.82 dB** | −1.54 dB | 15.7 dB | 66 ms |
| 串联 GTCRN→自训练 | +5.84 dB | −0.50 dB | 14.1 dB | 372 ms |
| 经典谱减法 | −2.66 dB | +4.68 dB | 1.4 dB | 20 ms |
| 理论上限（掩蔽+带噪相位） | +11.9 dB | — | — | — |

**泛化能力**（把 2 个 DEMAND 场景完全排除在训练外）：

| | 未见场景（广场/公园） | 已见场景 | 泛化代价 |
|---|---|---|---|
| 自训练 MLP | +6.08 dB | +6.86 dB | **仅 0.78 dB** |

**其它实测结论**
- 掩蔽类降噪有硬上限（保留带噪相位）：合成基准相位上限 +4.88 dB、理想掩蔽 +6.35 dB；
- 自训练模型**不是过拟合**：留出噪声类型实验里，未见类型上 +4.36 dB，甚至高于已见类型的 +3.12 dB；
- 经典谱减法在 babble（嘈杂人声）这类间歇噪声上会失效（噪声估计假设不成立）；
- 原程序的"带阻滤波"是 100 Hz 宽的陷波器，实测对白噪仅 +0.30 dB、对 50 Hz 工频无效——属滤波器设计演示，不是降噪方法。

## 4.1 为什么换成"自己刚录的 data.wav"后，感觉效果一般

结论先说：**模型并没有变差，"难听出效果"主要来自测试素材本身的性质。**

**先看事实**：`data.wav` 在不同时期是三份完全不同的素材（用文件指标区分）：

| 文件 | 峰值 | 静音段/语音段 | 说明 |
|---|---|---|---|
| 最初的 MATLAB 原始录音 | 0.329 | **−71.5 dB** | 几乎无底噪，最适合做"干净参考" |
| 你 9/23 深夜录的那条 | 0.036 | −58.5 dB | 电平很低，环境安静 |
| **你现在录的（9/24 上午两条）** | 0.88 / 0.99 | **−50.2 / −47.9 dB** | 有明显环境底噪（−48 dB 左右） |

**再用实验说明模型没变差**（同一模型、同一批真实噪声 @5 dB，只换"干净参考"）：

| 用来混合的"干净语音" | ΔSNR |
|---|---|
| 训练时用的语音段 | +5.06 dB |
| **你现在录的 data.wav** | **+4.94 dB** |

差距只有 **0.12 dB** —— 也就是说，**在"叠加同样的噪声再降噪"这件事上，模型对你的录音和训练语音表现几乎一样**。

**那为什么主观上觉得"一般"？三个原因：**

1. **降噪器只能压噪声，不能把人声变干净**。你的录音本身已含 −48 dB 的环境噪声，这部分噪声在"降噪前"就已经存在，听感上的改善自然不如"干净语音+人工加噪"那种对照明显；
2. **底噪大的录音当参照，"干净"的标尺就低了**。对数谱失真等指标衡量的是"与参照的接近程度"，参照本身带噪时，模型做得再好也看不出大差别；
3. **录音里的环境噪声（键盘、空调、房间混响）不等于我们训练用的噪声类型**，属于域外噪声，模型对它的抑制不如对训练噪声那么干净利落。

**该怎么做（按收益排序）**：

1. **录音时找安静环境、离麦克风 15~20 cm、电平拉高**（峰值 0.3~0.9 之间最理想）——这是提升最大的一步；
2. 用 `python check_corpus.py` 先体检：现在会逐个文件报**底噪/语音段比值**，超过 −40 dB 会直接标
   「← 底噪偏大」并提示"当干净参考会教模型保留噪声"；
3. 想听出降噪效果，用 `python ab_listen.py`（自动做响度对齐，并造出 −5 dB 的吵闹对照），
   或者干脆**用手机在嘈杂环境录一段当测试素材**——那种素材降噪前后的差别最直观；
4. 想让模型更懂你的环境：把你自己在安静环境录的语音加进语料，重训一版。

## 4.2 为什么 GTCRN 在"强噪声素材"上明显更强（精确诊断）

用用户提供的配对素材（`原始测试音频/data.wav` 干净版 + `加噪声.mp3` 加噪版）做**有参考的精确测量**。

**素材鉴定**：白噪声（各频带 ±1.3 dB 内平坦）、44.1 kHz 立体声 MP3、**真实 SNR = +3.6 dB**（用干净版精确算出）。

| 方法 | 最优增益 | 输入噪声 | 输出残留 | **噪声减少** |
|---|---|---|---|---|
| 带噪输入 | −1.62 dB | −3.6 dB | −3.8 dB | 0.3 dB |
| **GTCRN 预训练** | +4.94 dB | −3.6 dB | −13.3 dB | **9.7 dB** |
| 自训练 MLP | +8.81 dB | −3.6 dB | −7.8 dB | 4.2 dB |
| 串联 | +2.99 dB | −3.6 dB | −5.6 dB | 2.1 dB |

**SNR 扫描**（同一段干净语音 + 白噪声，逐点用真实参考测量噪声减少量）：

| 输入 SNR | −10 | −5 | 0 | **+3.6** | +5 | +10 | +15 | +20 |
|---|---|---|---|---|---|---|---|---|
| GTCRN | +16.6 | +14.8 | +12.7 | **+11.0** | +10.3 | +8.0 | +5.4 | +2.6 |
| 自训练 MLP | +11.1 | +8.5 | +7.2 | **+5.7** | +4.8 | +1.4 | −0.1 | −3.5 |

**结论（这也是"为什么我们的模型看起来一般"的答案）**：

1. **不是噪声类型不够**：白噪声正是训练用过的 8 类之一；SNR +3.6 dB 也落在训练区间 −5~+20 dB 内；
2. **是训练 SNR 分布偏了**：均匀采样导致只有约 1/5 样本在 0 dB 以上，模型成了"低 SNR 专精"——
   而 GTCRN 训练用的 DNS3 数据里**大量是近真实、噪声不强的样本**，所以全区间都稳；
3. **自训练模型在 +15 dB 以上会"帮倒忙"**（−0.1 / −3.5 dB）：音频本来够干净时它会削掉语音；
4. 在 +3.6 dB 处扫描预测 +5.7 dB、实测 4.2 dB，**说明该素材上的表现完全正常，没有异常**；
5. **格式因素被排除**：16k→44.1k→16k 重采样往返只差 0.09 dB（`diagnose_mp3.py` 可复现；
   MP3 编码的独立影响需 ffmpeg 才能测，预计影响也小——MP3 损失主要在 16 kHz 以上，而本项目只用到 8 kHz）。

**改进方向**（尚未实施）：① 按 SNR 分层采样、提高 0~20 dB 样本权重；② 抬高训练 SNR 下限；
③ 对安静帧的噪声抑制加惩罚（或改用幅度谱损失）；④ 把用户自己录的真实素材加入语料做域匹配。

> 方法学教训：早期用"无参考指标"（静音帧/语音帧能量比）估计强噪声素材，得出"自训练只降了 1.1 dB"
> 的结论，与精确测量（4.2 dB）不符——**没有干净参考时，无参考指标在强噪声+增益变化下很不可靠**，
> 诊断这类问题必须用配对素材或 SNR 扫描。

## 4.3 噪声库到底是什么（澄清"文件都一样 / 像奇怪音效"）

**噪声库分两块**，来源与用途完全不同：

| 位置 | 数量 | 来源 | 说明 |
|---|---|---|---|
| `models/noise_bank/noise_*.wav` | 8 个 | **本程序程序化合成** | 白噪/粉红/布朗/50 Hz 工频/键盘敲击/嘈杂人声/车内/空调 |
| `models/noise_bank/real/<场景>/ch01..ch16.wav` | 160 个 | **DEMAND 数据集**（Zenodo，CC BY 4.0） | 10 个真实环境 × 16 通道 |

**为什么"看起来每个文件都一样"？**（实测核对，非推测）

1. **文件名相同**：DEMAND 每个场景都是 `ch01..ch16.wav`（16 个麦克风的通道号）；
2. **文件大小完全相同**：每个场景是**5 分钟同步多通道录音**，所以 16 个文件都是
   96000172 字节（= 300 秒 × 16 kHz × 16 bit + 头），10 个场景也彼此相同；
3. **但内容全都不同**：全库 160 个文件 → **160 个不同 MD5，无任何重复**；
4. **同场景通道间高度相关是正常的**：多个麦克风录的是同一段声音，实测相关系数
   洗衣机 0.96~1.00（全向机器噪声）、厨房 0.87~0.91、公园 0.25~0.38（声源分布在不同方向）；
   不同场景之间则完全不同。

**"像奇怪的互联网音效合集"**：顶层那 8 个是**程序合成**的，其中「键盘敲击」本来就是脉冲串
（听着像哒哒音效），「嘈杂人声」是用语音素材变调叠加出来的。它们不是下载来的素材。

**副作用一：真实录音电平极低**

实测 DEMAND 各场景 RMS 只有 **0.0016~0.080**（合成噪声是 0.02~0.19）。直接播放会又轻又闷，
容易让人以为"文件坏了/不是噪声"。统一增益后试听：

```powershell
python listen_noise.py                               # 依次试听（自动增益到统一响度）
python listen_noise.py --export results/noise_demo   # 导出成文件慢慢听
python check_noise_lib.py                            # 去重 / 通道相关性 / 声学特征
```

**副作用二：真实录音含大量次声（<20 Hz）**

| 场景 | <20 Hz 占比 | 300 Hz~3 kHz（语音关键带） |
|---|---|---|
| DEMAND_DWASHING | 98.0% | **0.2%** |
| DEMAND_OOFFICE | 80.1% | **0.3%** |
| TCAR | 35.8% | 0.0% |
| PCAFETER | 17.6% | 36.2% |
| （10 场景平均） | 46.7% | 13.8% |

次声听不见、也不影响语音，但会**扭曲"按总能量计的 SNR"**：含次声时标称 5 dB SNR，
对人声频段的实际干扰远小于 5 dB（任务偏易）。实测对照（真实噪声 @5 dB）：

| 噪声处理 | 自训练 MLP | GTCRN |
|---|---|---|
| 原始（含次声） | **+8.05 dB** | +0.02 dB |
| 高通 60 Hz 滤掉次声 | +4.06 dB | +3.80 dB |
| 合成噪声（无次声）对照 | +5.39 dB | +2.93 dB |

**结论：含次声与滤净后的数字不可直接比较**，报告里必须注明是否做过高通。
体检与预处理：`python check_audio_health.py`（报告各频带占比；加 `--fix-dir 目录`
可把噪声库高通滤波后另存一份用于训练）。

### 4.4 白噪声专项：为什么自训练模型看起来"对白噪声效果不佳"

**先给结论：不是白噪声的问题，也不是训练集里缺白噪声**（8 类合成噪声里就有白噪声，
SNR 覆盖 −5~+20 dB）。三组实验（`python diagnose_white.py`）说明真正原因是三件事叠加。

**实验 A：三种噪声的 SNR 扫描（噪声减少量 dB，真实参考计算）**

| 输入 SNR | 白噪（自训练 \| GTCRN） | 粉红 | 车内 |
|---|---|---|---|
| −10 dB | **+11.9** \| +13.0 | +11.3 \| +10.8 | +12.3 \| +12.5 |
| −5 dB | **+9.8** \| +9.1 | +8.7 \| +7.0 | +9.9 \| +8.9 |
| 0 dB | **+6.9** \| +4.9 | +6.5 \| +3.2 | +9.9 \| +5.1 |
| +5 dB | **+5.9** \| +0.6 | +5.3 \| −0.6 | +8.7 \| +1.0 |
| +10 dB | **+4.4** \| −4.0 | +3.7 \| −4.4 | +5.8 \| −3.6 |
| +20 dB | **+2.2** \| −13.5 | +1.5 \| −12.9 | +1.7 \| −13.6 |

读法：**自训练模型在 −10 ~ +5 dB 全面优于 GTCRN**，在 +10 dB 以上两者都在退化，
但自训练退化得慢（GTCRN 在 +20 dB 时是 −13.5 dB，等于大幅帮倒忙）。
三种噪声的趋势**完全一致** → 这是"训练 SNR 分布"的锅，不是白噪声特有现象。

**实验 B：噪声底估计精度（@5 dB，与真实噪声谱对比）**

| 噪声 | 相关系数 | 平均绝对误差 | 系统性偏差 |
|---|---|---|---|
| 白噪 | **0.023** | 5.70 dB | +5.11 dB（高估） |
| 粉红 | 0.621 | 5.79 dB | +5.20 dB |
| 车内 | **0.896** | 12.75 dB | +12.34 dB |

白噪声的**逐频点估计几乎没有相关性（r≈0.02）**——因为白噪声在频域和时域都没有结构，
用"最小值统计"去估它只能得到纯统计噪声。而车内噪声 r=0.90（低频集中、时域稳定）。
这解释了自训练模型对"车噪"最强（+8~+9 dB）、对白噪最弱（+5~+6 dB）。

**实验 C：瓶颈究竟在哪（把"同域真值"噪声底喂给模型）**

| 噪声 | ① 模型自带估计 | ② 同域真值（估计得更准） | 差值 |
|---|---|---|---|
| 白噪 | **+4.97** | +0.46 | **−4.50** |
| 粉红 | +4.92 | +0.69 | −4.23 |
| 车内 | +8.44 | +7.43 | −1.01 |

**把"更准的噪声底"喂进去反而更差** → 瓶颈不是噪声估计精度，而是**模型自身的掩蔽能力 /
训练 SNR 分布**。模型只认它训练时那套特征（含那 +5 dB 的系统性偏差），换一套就掉出分布。

**实验 D：为什么主观上"GTCRN 明显更好"——查你那段素材（白噪，真实 SNR +3.6 dB）**

| 方法 | 噪声减少 | 对数谱失真（越小越保真） |
|---|---|---|
| 带噪输入 | — | 39.07 dB |
| **GTCRN** | −0.63 dB | **22.46 dB（改善 +16.6 dB）** |
| 自训练 MLP | −2.75 dB | 38.11 dB（改善 +0.96 dB） |
| 串联 | −1.11 dB | 38.92 dB |

**差别不在"压掉多少噪声"，而在"语音保真"**：GTCRN 把频谱显著拉回干净语音附近（+16.6 dB），
自训练模型几乎没改善频谱形状（+0.96 dB），而且在 +3.6 dB 这种"噪声已不是主导"的条件下
它会略微伤语音。所以耳机里听到的是**GTCRN 更干净、自训练更"糊"**——这与"白噪声"无关，
换成粉红/车噪也是同样的排序。

**改进方向（若要真正提升白噪声表现）**

1. **按 SNR 分层采样**，提高 0~+15 dB 样本权重（当前均匀采样让模型偏科低 SNR）；
2. **训练时也注入"高 SNR 样本"** 并加强安静帧的噪声抑制约束（治它在 +10 dB 以上伤语音）；
3. 但要注意：**白噪声是最难的一类**（无结构可利用），期望值应低于车噪/工频这类有结构噪声。

## 5. 已知限制

1. **训练 SNR 分布偏"低 SNR"**：均匀采样在 −5~+20 dB，导致模型在高 SNR（≥+10 dB）区间表现弱、
   甚至在 +15 dB 以上"帮倒忙"；这是 4.4 节三组实验共同指向的主因；
2. **干净语音只有约 25 秒**（同一说话人、同一设备）→ 跨说话人/跨录音环境的泛化尚未验证；
   而且现有素材里 `manba.wav` 底噪偏大（−28 dB），并不算理想的"干净参考"；
3. **主观"更干净"往往来自谱保真而非噪声压制**：在强噪声素材上 GTCRN 的对数谱失真改善
   达 +16.6 dB，自训练只有 +0.96 dB（4.4 节实验 D）——评估时必须两个指标一起看；
4. **白噪声是最难的一类**（频域/时域都无结构可借，逐频点估计相关性仅 0.02）；
   对它有结构可利用的车噪/工频效果明显更好；
5. 模型强弱**依赖测试集**（合成 vs 真实、低 SNR vs 高 SNR），报告结论时要注明测试条件；
6. 未测感知指标（PESQ / STOI），这两项更贴近主观听感；
7. 训练脚本仍是单文件、单进程；数据规模再大需要换成批量化/GPU 方案。
