# 更新说明：音乐音源分离与语音处理修复

日期：2026-10-05。项目：`E:\dsp\dsp_py`。

本次已实现人声/伴奏提取、四轨分离、同步试听、音量混音与导出，并修复此前发现的采样率、后台任务、训练标签、数据划分、尾帧、导出和指标说明问题。原有 Tkinter 语音界面保留，右侧新增音乐工作区。

## 1. 已完成的新功能

| 功能 | 实际行为 |
|---|---|
| 人声 / 伴奏提取 | VR 与 RoFormer 两种模型可选择，输出独立 WAV |
| 四轨分离 | HTDemucs4 输出人声、鼓、贝斯、其他，另外合成伴奏 |
| 模型下载与选择 | 自动检查本地模型，支持预下载；可选下载源和 CPU / auto / CUDA |
| 同步试听 | 各轨共用播放游标；播放/暂停/停止、拖动定位、切换轨道 |
| 分轨混音 | 每轨 0～2 倍音量、静音、独奏；原曲/人声/伴奏快捷选择 |
| 混音导出 | 保存当前混音为浮点 WAV 或 24 位 FLAC，附音量、采样率、来源 JSON |
| 峰值保护 | 混音超过满幅时对全部声道统一降低增益，保留各轨比例 |
| 音轨导出 | 每次创建独立目录，保存全部输出和结果清单 |
| 后台任务 | 独立进程处理，显示阶段与进度，可以取消；错误保留日志 |
| 历史结果 | 自动列出成功结果，可再次打开；取消目录不作为成功结果 |
| 文件与声道 | 单声道和立体声，恢复原采样率与原样本数；M4A 等增加 PyAV 解码 |
| 小窗口操作 | 分轨区可滚动，四轨及派生伴奏控件在缩小窗口后仍可访问 |

四轨默认混音使用四个真实输出，不再叠加派生伴奏和原曲，避免重复加音。RoFormer 的 `instrument` 名称统一为「伴奏」，不会出现两条重复伴奏轨。

三个模型已经下载至 `models/music/`，均用真实模型完成 CPU 分离。音乐处理调用 pymss 的公开 API，没有复制 pymss-studio 的前端源码。

## 2. 此前问题与修复方式

| 问题 | 已做的修复 | 对应文件 |
|---|---|---|
| MLP 以 16 kHz 训练，44.1/48 kHz 输入直接推理 | 按模型元数据重采样，输出恢复原采样率与长度；修正界面、试听和诊断脚本传参 | `core/enhance.py`、`app.py`、相关脚本 |
| 导入新素材时后台旧结果覆盖新素材 | 每个任务绑定素材版本、任务 ID、音频副本和采样率；过期结果直接忽略 | `core/tasks.py`、`app.py` |
| 录音完成覆盖随后手动导入的素材 | 录音始终归档，只有版本仍一致才自动载入 | `app.py` |
| GTCRN 多线程共享状态缓存 | 同一个模型实例的推理加锁，避免 reset/run 交叉 | `core/gtcrn.py` |
| 大数组转十六进制经队列传输 | 语音结果用内存对象传递；音乐通过文件和结构化事件返回 | `app.py`、`core/tasks.py`、`music_worker.py` |
| `abs(noisy)-abs(clean)` 被当作噪声幅度 | 使用实际缩放后的 `noisy-clean` 残差，IRM 为 `|S|/(|S|+|N|)` | `core/data.py`、`core/model.py`、评估脚本 |
| 重叠窗口随机拆分造成训练/验证泄漏 | 先按素材内容哈希分组，合并重复拷贝，再切非重叠片段；保存划分清单 | `core/corpus.py`、`train_model.py` |
| 只有一个素材时无法分组 | 改为互不重叠的时间划分，明确不代表跨说话人泛化 | `core/corpus.py` |
| 评估无法证明与训练集隔离 | 优先复用模型验证清单并核对素材哈希；旧留出模型缺少依据时拒绝泛化评估 | `bench_models.py`、`eval_compare.py`、`test_overfit.py` |
| STFT 舍弃不足一帧的尾部 | 向右补齐末帧，逆变换后裁回原长度；修复末尾成片静音 | `core/dsp.py`、`core/gtcrn.py` |
| 教师特征配置被忽略 | 按模型记录选择 MS 或 GTCRN 残差；GTCRN 模式不允许缺少必需特征；严格检查形状 | `core/enhance.py`、`core/data.py` |
| “串联”只改变特征来源 | 改为先 GTCRN 增强，再将其波形送入 MLP，明确是顺序处理 | `core/enhance.py` |
| 测试与演示默认音频路径不存在 | 使用实际示例、录音和原项目音频位置；训练体检与界面采用相同来源 | `core/corpus.py`、`smoke_test.py`、`check_corpus.py`、试听脚本 |
| 导出固定文件名互相覆盖 | 语音使用保存对话框和带时间/算法的默认名称；音乐任务/音轨导出创建独立目录 | `app.py`、`music_panel.py` |
| 无参考指标被说成真实 SNR/人声失真 | 显示高低能量对比、低能量帧下降、高能量帧保留、频谱改变量；不足以估计时不输出可靠值 | `core/metrics.py`、`app.py` |
| 音频长度错误被自动拉伸掩盖 | 处理结果和评估都要求等长，错误直接报告 | `app.py`、`core/metrics.py` |
| 训练覆盖旧模型或取消后状态混乱 | 新训练存为独立版本，支持取消、选择版本；模型原子保存，校验权重结构和数值 | `train_model.py`、`core/model.py`、`app.py` |
| 原有主界面持续出现布局警告 | 改用 Matplotlib constrained layout；原有图形交互回归通过 | `app.py` |

STFT 为兼容旧模型保留原帧起点；Hann 窗开头少量样本仍受原来的归一化阈值影响。本次解决的是末尾未覆盖造成的成片丢失，没有声称无损重建每一个边界样本。

## 3. 模型重新训练及实际结果

修复不只停留在训练脚本：已完成一次 18 轮完整训练，输出至：

`models/runs/20261005_fixed_full/`

其中包括 `denoise_mlp.npz`、`training_log.json`、`eval_report.json`、`split_manifest.json`。标签版本为 `irm_actual_noise_v2`，模型记录了对应划分 ID。最佳验证权重保存在第 13 轮，训练阶段约 450 秒。

实际可用素材去重后约 20 秒，5 个独立内容来源；4 个训练、1 个验证。训练使用 30% 真实噪声抽样和合成噪声。划分保障素材内容隔离，不证明说话人独立。

当前 `models/active_model.json` 指向该修正版，旧版 `models/denoise_mlp.npz` 原样保留，可在左侧「模型」页选择。新版与旧版的标签及训练划分不同，不能直接比较训练损失大小。

在相同固定验证语音上，6 类合成噪声 × 0/5/10 dB，共 18 个用例：

| 方法 | 平均 ΔSNR | 对数谱失真改善 | 分段 SNR 改善 | 低能量段抑制 |
|---|---:|---:|---:|---:|
| 经典谱减法 | +5.57 dB | +7.43 dB | +4.69 dB | 8.9 dB |
| 原版 MLP | +4.28 dB | +1.44 dB | +3.20 dB | 12.6 dB |
| 修正版 MLP | +3.10 dB | +8.18 dB | +4.89 dB | 22.1 dB |

修正版在本次测试中的频谱、分段 SNR 和低能量段抑制更好，总 SNR 提升下降。另一次 8 条随机合成样本评估得到平均 ΔSNR +1.42 dB，但分段 SNR 从 3.58 降到 0.87 dB，说明部分素材仍存在语音过抑制。不能把修正标签说成所有听感都变好。

旧版没有可靠的语音来源隔离证明，因此上表用于同输入行为对照，不作为旧版泛化结论。数据量很小，仍需要更多干净语音与人工试听。之前文档中的旧指标、所谓“硬上限”及泛化结论不再作为当前版本的性能依据。

此外完成一个小规模 GTCRN 特征训练版本，仅用于验证“训练特征 → 保存 → 重载 → 48 kHz 推理”的流程，不替换当前完整训练模型。

## 5. 现在怎样使用

当前电脑直接双击 `E:\dsp\dsp_py\run_windows.bat`，切换右侧「音乐分离 / 分轨混音」。导入歌曲，先用 VR 模型和 CPU 跑通，再按需要选择 RoFormer 或四轨模型。

想提取伴奏：完成分离后点「听伴奏」，再「导出混音」。只保留人声时同理。需要鼓或贝斯时选择四轨模型，独奏对应音轨，或导出全部音轨。

在其他 Windows 电脑上，先装 Python 3.12 并运行 `setup_music_windows.bat`。拷贝源码、模型和示例即可，不必拷贝本机 `.venv`；需要离线音乐分离时带上 `models/music/`。验证清单记录原始素材绝对路径，迁移后要恢复对应素材路径或重新生成划分。
