# 换电脑启动修复

日期：2026-10-10。

V2 补丁修正首次迁移补丁中的多启动器检测漏洞。

## 报错原因

截图中的 `No Python at C:\Users\26824\...\Python312\python.exe` 来自复制过去的虚拟环境。`.venv/pyvenv.cfg` 和 `.venv-speakers/pyvenv.cfg` 的 `home` / `executable` 指向原电脑创建环境时的 Python；另一台电脑没有该路径，启动器执行虚拟环境中的 `python.exe` 就失败。

这不是音频算法在使用该用户路径。原启动器只检查 exe 是否存在，没有检查它能否运行，因此未拦住失效环境。现已修复。[Python 官方说明](https://docs.python.org/3/library/venv.html#how-venvs-work)也指出虚拟环境通常不能直接迁移，需要在目标位置重建。

第二张截图中的 `Python\Launcher\py.exe ... WindowsApps\py.exe` 报错来自首次补丁：PowerShell 找到多个 `py.exe` 后，脚本把整个路径数组当成一个命令执行。V2 显式枚举每个启动器并单独检测，跳过 WindowsApps 别名；启动器失效或没有 Python 3.12 时继续查找其他入口，之后仍可从 PATH 和注册表检测本机解释器。

## 另一台电脑的操作

1. 在该电脑安装 **64 位 Python 3.12**。安装位置和用户名可以不同；脚本从本机 Python Launcher、PATH 和注册表检测，不包含个人固定路径。
2. 把 **`启动迁移修复_V2_20261010.zip`** 解压到已有 `dsp_py` 目录，覆盖同名文件。`bootstrap_windows.ps1` 必须与 bat 启动器同目录。已使用首版补丁也需要重新覆盖。
3. 运行 `setup_music_windows.bat` 安装主环境；使用双人分离时再运行 `setup_speakers_windows.bat`。
4. 运行 `run_windows.bat`。

已复制的失效环境由脚本改名保留为 `.venv.broken_时间_随机ID` 或 `.venv-speakers.broken_...`，再创建新环境。检测不到本机 Python 时先报安装提示，不移动旧环境。下载/安装失败会返回失败状态，可查看窗口日志后重试。

新启动器在主环境失效或基础依赖缺失时也会自动重建并安装主环境；双人环境仍由其安装脚本单独配置。第一次安装依赖需要网络。脚本只重建项目内环境，不修改模型、录音、分离结果，也不安装全局 Python。

## 复制项目应带哪些文件

携带源码、`core/`、`docs/`、安装/启动脚本、requirements 文件、`models/` 中运行所需模型及 `samples/`。自己的音频和处理结果按需要携带。

排除 `.venv/`、`.venv-speakers/`、`.cache/`、`__pycache__/`、`backups/` 和 `models/noise_bank/`；最后一项是训练噪声库，运行和分离不需要。普通 Python venv 不是免安装运行包，修改 `pyvenv.cfg` 的 home 也不能保证已有扩展和启动脚本正确迁移。

## 改动及验证

- 新增 `bootstrap_windows.ps1`：检测 Python 能力、发现本机解释器、安全保留失效环境、重建、安装及启动。
- 更新三个 Windows bat：共用检测流程，保留真实退出码。
- 更新 `core/speakers.py`：启动子进程前检测双人环境；失效时提示在本机重建。
- 更新 README 并提供覆盖补丁，不携带旧虚拟环境。
- V2 修复多个 `py.exe` 路径拼接、WindowsApps 别名优先和首个启动器失效导致的检测中断，并兼容旧启动器将版本列表写入标准错误输出的行为。
- 修正旧 Python Launcher 的参数引用方式：`-3.12` 不再加多余引号，避免被传给默认版本的 Python 并报 `Unknown option: -3`；本机默认 Python 为 3.14 时仍能选择 3.12。

`verify_portable_startup.py` 实测 **7/7 通过**：保留正常环境；复现 `No Python at` 并在中文/空格/`&` 目录重建；独立双人环境重建和幂等复用；无本机 Python 时保留旧环境；检查启动脚本无个人路径；多个启动器共存并且 WindowsApps 别名排在 PATH 首位；首个普通启动器失效时回退至第二个。多启动器测试还在同一 PATH 下运行首版脚本，确认旧版失败、V2 成功。

测试通过 Windows PowerShell 运行，没有重新安装当前正常环境中的大体积依赖；新电脑的联网下载仍取决于该电脑网络。验证记录在 `results/verification_portable_20261010/`，源码备份在 `backups/before_portable_startup_20261010/`。

V2 修改前的启动脚本另存于 `backups/before_multi_launcher_fix_20261010/`。
