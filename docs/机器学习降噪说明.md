# 机器学习降噪方案说明（含数据集来源）

> 回答两个问题：**为什么可行**、**训练数据从哪来**。

---

## 1. 总体思路：把降噪变成"逐频点该保留多少能量"的回归问题

传统降噪（原 MATLAB 版）是**人设计规则**：设计一个 1500~2100 Hz 的带阻滤波器压掉窄带干扰，
或按公式 `|S|² = max(|Y|² − α|N|², β|Y|²)` 做谱减，参数（α、β、滤波器通阻带）全靠人工调。

机器学习降噪是**从数据里学规则**：让网络看一眼带噪语音的时频谱，直接输出一张
"保留系数图"（掩蔽）：

```
带噪语音 x(t)
   │  STFT（512 点窗 / 128 点跳，32 ms 窗长 / 8 ms 帧移）
   ▼
复数谱 X(f,t) ──► 幅度 |X| ──► 20log10 ──► 归一化 ──► 神经网络 ──► 掩蔽 M(f,t) ∈ [0,1]
   │                                                                      │
   └───────────────────── 复数谱 × M ──► ISTFT ──► 降噪后波形 ◄───────────┘
```

网络学的是"每个时频点该保留多少"，这就是最小的机器学习语音增强模型
（Speech Enhancement by Time-Frequency Masking），也是当前主流深度降噪模型
（DNN/CRN/DeepFilterNet）的共同骨架。

---

## 2. 训练数据从哪来（不用下载任何数据集）

监督学习需要 **(带噪, 干净) 成对数据**。公开数据集（VoiceBank-DEMAND、MS-SNSD、
MUSAN、DEMAND）动辄数 GB，下载慢、版权也麻烦。而学界最常用的配对方法本来就是
**"干净语音 + 合成噪声"**（VoiceBank-DEMAND 数据集自己就是这么造的），所以本项目
在本地复现这套流程：

| 环节 | 做法 | 代码位置 |
|---|---|---|
| **① 干净语音** | 用你自己的录音：界面「① 录音」录的每条都会归档到 `recordings/`（训练时自动全部纳入），或「导入干净语音…」选已有文件；也可直接用 `data.wav`、`manba.wav`。按 1~4 秒切段 | `core/data.py: load_clean_pool()` |
| **② 噪声** | 程序化合成 8 类，每类可无限生成：白噪声、粉红噪声(1/f)、布朗噪声(1/f²)、50 Hz 工频嗡嗡声、键盘敲击脉冲、babble 嘈杂人声（用语音素材变调叠加）、车内噪声、空调低鸣。**可选**再叠加真实噪声数据集（DEMAND/MUSAN/ESC-50），见 `download_datasets.py` | `core/data.py: make_noise()` / `load_noise_pool()` |
| **③ 混合** | 逐样本按指定 SNR 缩放后相加：`x = s + √(P_s / (P_n·10^(SNR/10))) · n`，SNR 精确可控 | `core/data.py: mix_at_snr()` |
| **④ 标签** | 理想比值掩蔽 IRM = \|S\| / (\|S\| + \|N\|)，由干净谱和噪声谱自动算出，**不需要人工标注** | `core/data.py: _irm()` |
| **⑤ 训练样本** | 每个 epoch 现场随机组合「语音段 × 噪声类型 × SNR(−5~20 dB) × 随机种子」 | `core/data.py: MixtureDataset` |

**所以数据集不是一份固定文件，而是每次迭代即时合成的**：

- 训练集规模 = 无限（每轮都是新噪声、新 SNR、新相位）；
- 干净参考已知 → 可以精确算降噪指标（这是真实带噪录音做不到的）；
- 完全离线，零下载，答辩时可以现场演示"造数据 → 训练 → 降噪"全流程。

想先看看噪声长什么样：

```powershell
python train_model.py --clean ..\data.wav --epochs 1 --export-noise models\noise_bank
# 生成 models\noise_bank\noise_*.wav 共 8 个文件，直接试听
```

**想换成真实噪声？** 把 `models/noise_bank/*.wav` 换成真实录音（如 MUSAN、DEMAND 的
噪声片段），或在 `core/data.py` 的 `NOISE_TYPES` 里加一类"从文件读取噪声"即可，
其余流程完全不变。

## 3. 网络结构与训练细节

```
输入   : 257 频点 × 3 类特征 × 13 帧（当前帧 ±6 帧）= 10023 维
         特征① 带噪对数幅度谱  20log10|Y|              —— 观测
         特征② 噪声底估计      10log10(N_est)          —— 判断"这点是噪声还是语音"的依据
         特征③ 局部信噪比      20log10|Y| − 10log10(N_est)（钳位 [−20,40] dB）
隐藏层 : tanh(256) → tanh(128)
输出   : sigmoid(257) —— 每频点的掩蔽值 ∈ [0,1]
参数   : 约 263 万个（纯 NumPy，CPU 训练约 8 分钟）
损失   : 二元交叉熵（对 [0,1] 掩蔽回归的标准选择）
优化器 : Adam，学习率 2.5e-3，mini-batch 8 条语音（约 3000 帧）
```

**三个设计要点都是靠实验定下来的**（每一步都有对照数据）：

1. **必须有时间上下文**：只用单帧幅度谱时，网络分不清"语音+噪声"和"较强噪声"，
   只能学一个平均收缩（掩蔽标准差仅 0.18、逐频点相关 0.54），实测 ΔSNR 只有 +1.42 dB；
2. **必须给噪声底特征**：加上特征②③后，网络才知道每个时频点的局部信噪比，
   ΔSNR 提升到 +3.09 dB；
3. **上下文越宽越好**：±2 帧 → ±6 帧后 ΔSNR 进一步升到 **+4.04 dB**（见第 5 节）。

**推理时的后处理**：掩蔽沿频率方向做 `[0.25, 0.5, 0.25]` 平滑，抑制"音乐噪声"
（musical noise）；实测这一步还能再带来约 +1.5~1.9 dB。

**为什么不用 PyTorch？** 本机 Python 是 3.14，PyTorch 官方尚无 cp314 轮子
（[pytorch#156856](https://github.com/pytorch/pytorch/issues/156856)），装不上。
所以前向、反向传播、Adam 全部用 NumPy 手写（`core/model.py`，约 200 行），
好处是零依赖、可逐行讲解；263 万参数在 CPU 上 8 分钟就能训完。

## 4. 评估指标：为什么不能只看"SNR 提升"

调试过程中本项目实测出一个重要结论：

> **掩蔽类降噪保留带噪相位，因此 SNR 提升存在硬上限。**
> 4 秒语音、白噪声 @5 dB 输入时，即便幅度谱**完全准确**（用干净幅度 + 带噪相位重建），
> SNR 也只能到 9.99 dB，即相对带噪仅 **+5.0 dB**；用理想掩蔽 IRM 是 **+6.3 dB**。
> 18 个用例的平均上限为：相位 +4.88 dB、理想掩蔽 IRM +6.35 dB。

所以评估必须多指标一起看（`eval_compare.py` / `bench_models.py` 会一次性算全）：

| 指标 | 含义 | 方向 |
|---|---|---|
| ΔSNR | 信噪比提升，受上述相位上限约束 | 越大越好（有天花板） |
| LSD 对数谱失真 | 频谱包络与原干净语音的差距，反映**语音失真** | 越小越好 |
| SSNR 分段信噪比 | 逐帧信噪比平均，比整体 SNR 更贴近听感 | 越大越好 |
| 静音段噪声抑制 | 语音间隙处能量下降多少 dB，反映**噪声变小了** | 越大越好 |

也正因如此，本项目在经典谱减法上继续做了功课：早期版本用"开头若干帧均值"估噪声，
结果 SNR 反而 **−24 dB**（把语音一起减掉了）。最终改为**平滑最小值统计**：

- 单个周期图 bin 的功率服从指数分布，直接取最小值会严重低估噪声——
  实测估计/真实仅 **0.002（偏低 539 倍）**，导致过减量形同虚设；
- 先做 (9 频点 × 11 帧) 盒式平滑提高自由度，最小值偏差降到约 **2 倍**，
  再乘偏置 3.0，估计才可用于过减；
- 效果（单一用例）：白噪声 @5 dB 输入，SNR 从 5.00 → 9.91 dB（**+4.91 dB**）。
- 这个估计器后来还被复用为神经网络的**输入特征②**——经典方法与机器学习并非对立，
  好的信号处理先验正好是很好的网络输入。

## 5. 实测对比（复现命令 `python bench_models.py`）

固定基准：6 类噪声 × 3 档 SNR（0/5/10 dB）= 18 个用例，3 段语音均未参与训练。

| 方法 | ΔSNR | LSD 改善 | SSNR 改善 | 噪声抑制 | 相对上限 |
|---|---|---|---|---|---|
| 经典谱减法（含带阻滤波） | **−3.00 dB** | −5.00 dB | +3.51 dB | 7.9 dB | — |
| ① 仅带噪谱，±2 帧（1285 维，39.5 万参数） | +1.42 dB | +0.32 dB | +3.57 dB | 7.7 dB | 29% |
| ② +噪声底特征，±2 帧（3855 维，105 万参数） | +3.09 dB | +0.73 dB | +3.69 dB | 10.1 dB | 63% |
| ③ **+噪声底特征，±6 帧（10023 维，263 万参数）** | **+4.04 dB** | **+1.08 dB** | **+4.40 dB** | **12.2 dB** | **83%** |
| 理论上限：干净幅度 + 带噪相位 | +4.88 dB | — | — | — | 100% |
| 理论上限：理想掩蔽 IRM | +6.35 dB | — | — | — | 130% |

按噪声类型看平均 ΔSNR（模型③ vs 经典）：

| 噪声 | 白噪声 | 粉红 | 工频嗡嗡 | babble | 车内 | 空调 |
|---|---|---|---|---|---|---|
| 神经网络 | +0.9 | +3.3 | **+5.2** | **+4.2** | **+7.5** | **+3.1** |
| 经典谱减法 | −3.0 | −2.5 | −3.5 | −3.4 | −1.8 | −4.0 |

结论很清晰：**平稳宽带噪声两者相当，非平稳/类语音噪声只有神经网络稳得住**；
在这个 18 用例基准上神经网络全面优于经典基线，并已拿到相位上限的 83%。

> 注意：单个 4 秒样本、白噪声 10 dB 这类"最简单"的用例上，经典谱减法有时仍略优
> （它对平稳噪声的估计非常准）。所以工程上更合理的做法是两者都留着、按场景选，
> 本项目界面上正是这么做的（⑤ 神经网络 / ⑥ 经典谱减法）。

训练日志与逐样本明细见 `models/training_log.json`、`models/eval_report.json`；
可试听的 A/B 音频用 `python make_demo.py` 导出（干净 / 带噪 / 神经 / 经典 四件套）。

复现命令：

```powershell
python train_model.py --clean ..\data.wav ..\manba.wav   # 训练（约 8 分钟）
python bench_models.py                                   # 上表的对比基准
python eval_compare.py                                   # 更多噪声类型 × SNR 的详细报告
python smoke_test.py                                     # 算法自检 16 项
python make_demo.py                                      # 导出可试听音频
```

## 6. 常见疑问

**Q：只有 25 秒干净语音，数据够吗？**
能用，但这是**当前唯一的瓶颈**：三次实验（39.5 万 / 105 万 / 263 万参数）的验证损失
都停在 0.35 左右，说明限制来自数据多样性而非模型容量。想进一步提升：多录几分钟语音
（界面「① 录音」，几分钟就够），或把 `--epochs`、`--context` 调大。

**Q：为什么训练时验证损失会波动？**
训练集每轮是**新生成**的，验证集若也用新数据就不可比。本项目用 `fixed_batch()` 固定
了一批验证数据，因此 `training_log.json` 里的验证损失是可比、可用于选最佳模型的。

**Q：能上真实数据集/更大网络吗？**
可以。`core/data.py` 的接口不变，把 `load_clean_pool()` 指向真实语料
（如 VoiceBank-DEMAND 的干净语音）、`make_noise()` 换成读取真实噪声（MUSAN/DEMAND）即可；
网络换成 CRN/Transformer 也只是替换 `core/model.py` 里的前向与反向。换到 Python ≤3.13
环境就可以直接用 PyTorch 训练，再用 `core/enhance.py` 的同名接口推理。

**Q：试过"每种噪声单独训一个专精模型"吗？**
试过（思路：让每个小网络只面对一种噪声）。结论是收益有限：在只有 25 秒语音的前提下，
专精模型与通用模型的验证损失相近，而通用模型只需一个文件、界面里也无需先判断噪声类型，
工程上更简单。等语音数据变多，专精/多条件模型值得再试。

**Q：换成真实噪声数据集（DEMAND）训练会更好吗？**
不一定，取决于覆盖广度。本项目的实测对照（同一固定基准，6 类噪声 × 3 档 SNR）：

| 训练噪声来源 | ΔSNR | 逐类表现 |
|---|---|---|
| 程序化合成 8 类（默认交付版） | **+3.99 dB** | 6 类全部为正 |
| 只用真实噪声：1 个场景 / 160 秒 | +2.04 dB | 白噪 −0.3、空调 −1.2（明显退化） |

原因：160 秒单一场景（会议室）覆盖太窄，模型没见过的噪声类型上会掉；而合成噪声
虽然"假"，却覆盖了白噪/粉红/工频/脉冲/人声/车噪等 8 类形态。所以工程结论是：

- **合成噪声做主力**（覆盖面广、零下载、可无限生成）；
- **真实噪声做补充**：默认 `--file-noise-ratio 0.3`，建议真实噪声覆盖 3 个以上场景
  再调高到 0.5；想针对特定环境（比如你自己的办公室）优化，就多录/多下该环境的噪声；
- 训练时的验证集已改为**逐条确定性交替**使用合成与真实噪声，
  否则真实噪声池太小会让验证损失在 0.35~0.76 之间乱跳、无法用于选最佳模型。

**Q：能不能直接用别人训好的模型？**
能，本项目已集成 **GTCRN**（ICASSP 2024 官方实现，MIT 许可，DNS3 上训练）：
0.5 MB、原生 16 kHz、纯 onnxruntime 推理（**不需要 PyTorch**），模型文件在
`models/gtcrn/gtcrn_simple.onnx`，经 hf-mirror 国内镜像获取（HuggingFace 官网在
这台机器上不通，镜像可用）。

正确性不是"看起来能跑"就算：我们用官方仓库自带的输入/输出配对样本做了逐样本对齐，
**相关系数 0.99994**（`core.gtcrn.verify_against_reference()`），确认
STFT → 逐帧流式推理 → ISTFT 全链路与官方 PyTorch 实现等价。

真实 DEMAND 噪声 @5 dB、30 个用例上的三方实测：

| 方法 | ΔSNR | 对数谱失真改善 | 噪声抑制 | 耗时/4 秒 |
|---|---|---|---|---|
| GTCRN 预训练 | −1.16 dB | **+6.27 dB** | 2.8 dB | 296 ms |
| 自训练 MLP（本项目） | **+7.83 dB** | −1.55 dB | 15.7 dB | 66 ms |
| 串联 GTCRN→自训练 | +6.99 dB | **+0.38 dB** | 13.1 dB | 372 ms |

读法：GTCRN 走"保守保真"路线（谱失真最小、几乎不削人声，但 SNR 增益为负）；
自训练模型走"激进压噪"路线（SNR 增益最高，但有语音失真）；
**串联是唯一两个指标同时为正的方案**。所以三个都保留，界面上一键对比。

**Q：那"用预训练模型当老师"训练自己的模型有用吗？**
试过了（`--noise-prefix gtcrn`：把 GTCRN 的输入−输出残差当噪声底特征，替代自研的
最小值统计）。这是一个**负结果**：数据充足时（128 条真实噪声 + 8 类合成噪声、25 秒干净语音）
v4 略低于 v3（ΔSNR +5.13 vs +7.83，对数谱失真 −0.33 vs −1.55）。
结论：**训练数据够用时，直接训练优于蒸馏**；但干净语音极少（只有几十秒）时这条路值得启用
——数据越少，借外部知识越划算。命令保留在项目里，可随时复现。
