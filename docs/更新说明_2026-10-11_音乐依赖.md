# 音乐分离缺少 torch 修复

另一台电脑出现 `No module named 'torch'`，表示运行音乐分离的 Python 环境没有安装 PyTorch。下载模型不能代替安装依赖；在其他 Python 环境安装也不会让当前环境自动可用。

## 改动

- `bootstrap_windows.ps1`：原先运行模式只检查六个基础依赖，基础依赖齐全便跳过安装。现在同时实际导入 torch、av 和 pymss 的分离接口，缺失或加载失败时进入音乐依赖安装流程。
- 音乐安装流程在 `pip check` 后实际导入音乐依赖；原生库加载失败时安装脚本返回失败，不再直接报告安装成功。
- `requirements-music.txt` 显式加入 `torch>=2.7.1`。Windows 安装脚本仍先从 PyTorch CPU 源安装。
- `music_worker.py`：依赖导入失败时显示安装脚本、正确启动入口、当前 Python 路径及原始错误；日志保留完整异常。
- `setup_music_windows.bat`：失败提示指向实际错误和网络情况，避免所有失败都被描述成未安装 Python。

## 另一台电脑操作

关闭程序，在项目目录运行：

```powershell
git pull --ff-only
.\setup_music_windows.bat
.\run_windows.bat
```

安装需要联网。看到安装成功后再启动；如果安装失败，保留安装窗口中的错误信息。请通过项目的启动脚本运行，避免 IDE 或全局 Python 使用其他环境。

## 验证

- `verify_music_dependencies.py`：2 项回归通过。真实隔离 Python 环境中模拟只有基础包、音乐包完整、音乐包导入损坏三种状态，确认安装选择；不联网安装、不改现有环境。
- 模拟缺失 torch，验证 worker 返回可执行的修复说明和当前解释器路径，并保留原始错误。
- 本机主环境实际导入 torch、av 和 pymss 三个分离接口成功。
